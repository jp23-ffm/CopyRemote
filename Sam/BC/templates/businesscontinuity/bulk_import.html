Bulk CSV Import

    Upload a CSV file to perform a bulk update. The format is auto-detected from the header row.

    Supported formats: Server Import / Server Export / Application Import

    Server Import

    Updates server fields. hostname_unique is mandatory. Other fields are optional (empty = unchanged). Priority Asset, Live Play and Cluster only accept YES, NO or EMPTY: a line with another value is ignored and listed before the import, like a server listed several times with different values.

    • hostname_unique (mandatory): Server hostname
    • priority_asset: Priority Asset (YES/NO/EMPTY)
    • in_live_play: Live Play Status (YES/NO/EMPTY)
    • action_during_lp: Action during the Live Play
    • annotation: Annotation
    • cluster: Cluster (YES/NO/EMPTY)
    • cluster_type: Cluster Type
    • bc_exception: BC Exception (YES/NO/EMPTY): BC rules leave the server alone on the affected site
    hostname_unique;priority_asset;in_live_play;action_during_lp;annotation;cluster;cluster_type;bc_exception
server1;Yes;Yes;In ME until 24th;;No;;No
server2;No;Yes;In ME until 25th;;Yes;OPENSVC Cluster;
server3;;No;;;;;Yes

    Server Export

    The scheduled full export (; separated) can be loaded as is, to restore the values it holds. It is reduced to one line per server, then handled as a Server Import: SERVER_ID is the hostname, other columns are not imported. Values changed since the export will be overwritten and fields empty in the export will be cleared; a server whose lines disagree is refused.

    Application Import

    Updates application Live Play status. Both fields are mandatory. The file is the source: an application listed at least once with YES sets its servers to YES, and a server goes to YES as soon as one of its listed applications is YES. Applications absent from the file have no influence.

    • application_id (mandatory): Application identifier
    • in_live_play (mandatory): Live Play Status (YES/NO)
    application_id;in_live_play
APP001;Yes
APP002;No
APP003;Yes
